# Мультиязычный блог на Hugo → GitHub Pages

Готовый шаблон: статический блог на [Hugo](https://gohugo.io) с русской и английской версией, автодеплой на GitHub Pages через GitHub Actions. Своя тема (лёгкая, без внешних зависимостей) — ничего не сломается от чужого репозитория.

## Структура проекта

```
.
├── hugo.toml                      ← конфиг сайта (языки, заголовок, base URL)
├── content/
│   ├── ru/
│   │   ├── _index.md              ← главная страница (русская)
│   │   └── posts/
│   │       ├── _index.md          ← заголовок раздела "Посты"
│   │       └── pervyi-post.md     ← ТВОЙ ПЕРВЫЙ ПОСТ (заполнить)
│   └── en/
│       ├── _index.md              ← главная страница (английская)
│       └── posts/
│           ├── _index.md
│           └── first-post.md      ← YOUR FIRST POST (English version)
├── layouts/                       ← HTML-шаблоны (можно не трогать)
├── static/css/style.css           ← стили (тёмная тема, минимализм)
└── .github/workflows/deploy.yml   ← автодеплой при пуше в main
```

## Куда вписывать свой опыт

1. **Новый пост** → создаёшь файл в `content/ru/posts/название-поста.md` (и аналогичный в `content/en/posts/` для английской версии). Формат:

```markdown
---
title: "Заголовок поста"
date: 2026-07-17
summary: "Короткое описание для списка постов"
---

Текст поста в обычном Markdown.
```

   Важно: если дата в будущем относительно момента сборки — Hugo **не опубликует** пост (это фича, не баг). Ставь сегодняшнюю или прошлую дату.

2. **Готовый черновик-шаблон** уже лежит в `content/ru/posts/pervyi-post.md` и `content/en/posts/first-post.md` — там есть структура (что делал / бэктест / что пошло не так / выводы), просто впиши свой опыт с ботами под Solana и Polymarket вместо текста в скобках.

3. **Главная страница** — общее описание блога — правится в `content/ru/_index.md` и `content/en/_index.md`.

4. **Заголовок сайта, описание, автор** — в `hugo.toml`, секции `title` и `[params]`.

## Деплой на GitHub Pages — пошагово

1. Создай новый репозиторий на GitHub, например `blog`.
2. Залей туда содержимое этой папки:
   ```bash
   cd blog-template
   git init
   git add .
   git commit -m "init blog"
   git branch -M main
   git remote add origin https://github.com/ТВОЙ_ЮЗЕРНЕЙМ/blog.git
   git push -u origin main
   ```
3. **Обнови `baseURL`** в `hugo.toml` на реальный адрес:
   ```
   baseURL = "https://ТВОЙ_ЮЗЕРНЕЙМ.github.io/blog/"
   ```
   (если сделаешь репозиторий `ТВОЙ_ЮЗЕРНЕЙМ.github.io` — то есть репозиторий = юзернейм, — тогда baseURL будет просто `https://ТВОЙ_ЮЗЕРНЕЙМ.github.io/` без хвоста, это способ получить сайт на корневом домене без `/blog/` в пути).
4. В настройках репозитория: **Settings → Pages → Build and deployment → Source** выбери **"GitHub Actions"** (не "Deploy from a branch").
5. Пушни любой коммит в `main` — сработает workflow из `.github/workflows/deploy.yml`, соберёт сайт и задеплоит.
6. Смотри прогресс во вкладке **Actions** репозитория. Через 1-2 минуты сайт будет доступен по адресу из `baseURL`.

Дальше всё просто: добавил `.md` файл с постом → закоммитил → запушил → через минуту пост на сайте. Никакого отдельного хостинга, домена или денег не нужно.

## Локальная проверка перед пушем (по желанию)

Если хочешь посмотреть сайт локально перед публикацией:

```bash
# скачать бинарник Hugo (extended, версия под свою ОС) с https://github.com/gohugoio/hugo/releases
hugo server
# сайт откроется на http://localhost:1313
```

## Свой домен (опционально, тоже бесплатно в плане хостинга)

Если купишь домен (например на Namecheap/Cloudflare, ~$10/год), просто:
1. Создай файл `static/CNAME` с содержимым `твойдомен.ру`
2. У регистратора добавь DNS-запись типа `CNAME` → `ТВОЙ_ЮЗЕРНЕЙМ.github.io`
3. GitHub Pages подхватит домен автоматически при следующем деплое.

Сам хостинг остаётся бесплатным — платишь только за домен, если он тебе нужен.
